# Terminal output tools

Each terminal has Find, Copy selection, Copy output and Export controls. Ctrl+F (Cmd+F on macOS) opens terminal search while the terminal has focus. Enter/Shift+Enter move between matches; Escape closes search, restores the prior scroll position and returns keyboard focus to the terminal. Search text is never submitted to the shell.

Search supports case sensitivity and regular expressions, reports invalid expressions and highlights up to 1,000 matches. The count is capped and labeled `1,000+ matches`. Searches cover retained output, including wrapped lines; output already discarded by the configured scrollback limit cannot be recovered.

Terminal search remembers the last 20 different queries you searched for. Only a search run with Enter or Shift+Enter is remembered; the results that update while you type are not, and an empty query or one made only of spaces is ignored, as are spaces at the start and end of a query. With the search box empty, press the Up arrow to fill it with the most recent query and the Up arrow again for older ones, until the oldest; press the Down arrow to move back toward the newest and, past it, to an empty box. The arrows act only while the box is empty or still showing a recalled query, so they never interfere with editing text you typed, and they do nothing with Ctrl, Alt, Shift or Cmd held. A recalled query is only placed in the box; it is not sent anywhere and not remembered again until you press Enter. Searching a remembered query again moves it to the top. The list is shared by every terminal open in HRig and is kept in memory only: it is never saved to the workspace or the settings and never exported, and it is gone when HRig is closed or reloaded, because a query can contain a secret. There is no setting for it, and nothing is typed or sent to the shell or the seat.

Copy output and export use rendered plain text, join soft-wrapped rows and omit terminal escape/control sequences. Export opens a native save dialog, honors cancellation and reports write failures. Exports are snapshots of the active buffer, not continuous recording; applications using an alternate screen expose that active screen. The default filename is `terminal-output.txt`.

HTTP/HTTPS links require native confirmation before opening the system browser. Links with embedded credentials and non-browser protocols are rejected. Conventional file paths with extensions, optionally followed by `:line:column` or `(line,column)`, open in HRig after the existing backend confirms that they resolve inside the terminal's attached project. Relative links use that project root rather than inferring the shell's current directory. Soft-wrapped paths are joined for detection and underlined across rows. Paths containing spaces are detected only when enclosed in matching single or double quotes with a path separator before the first space (use `./my file.ts` for a project-root file); shell expansions and escaped quotes are not interpreted. Hard line breaks never join paths. Detection is bounded to 201 rows / 32 KiB per logical line. Remote file access uses the terminal's original connection even if the selected host/project has changed. Existing backend traversal, symlink and file-size protections apply.

These controls do not recreate the PTY or change OpenRig sessions. Reconnect remains a separate explicit control.

Search and output notices appear as overlays so opening/closing tools does not resize the PTY or trigger a full-screen program repaint.

Seat terminals show the seat name, runtime and current inventory activity (Working, Idle, Needs input, Running, Stopped or Activity unknown). Needs input uses the existing attention dot. Activity reuses inventory refresh without additional polling and becomes unavailable when inventory fails, the seat disappears, or another host is selected. Plain shells retain their shell header. The separate connection dot describes the terminal transport.

Host label and tint is off until you set one, and it changes nothing else. Run Set host label and tint in the command center, then give any saved connection a short label (up to 24 characters, for example PROD or DEV) and a color from a fixed list (red, amber, green, blue, violet or gray) and choose Save. Every terminal on that connection then shows the label beside the connection name in its header and a thin colored line along the top of the header, so a production shell is hard to mistake for a development one. Only the header changes: terminal text, colors and size, the panel layout and the tab titles stay as they are, and the header keeps its height. Clear the label and choose No tint to remove it. Labels are saved per connection in HRig's workspace file, not in the settings and not in the Settings export, are never sent to a terminal, a host or a seat, and a connection with nothing set looks exactly as before. HRig does not guess which host is production; you choose.

Command center lists Focus, Clear, Find, Reconnect and Saved snippets for each open terminal (with its host and terminal ID). Clear clears the local display/scrollback without sending a shell command. One-time reviewed action terminals are excluded. Snippets persist in workspace settings; selecting or saving one sends nothing. Insert pastes a single printable line at the current cursor without Enter. Multiline text, control characters and invisible Unicode formatting characters are rejected to prevent accidental submission. Review insert and run shows the exact text, host name and terminal ID and requires a separate explicit click to send Enter. Existing input at the terminal cursor is not cleared and will also be submitted. Check the target and existing input before using a snippet.

Snippet placeholders: a saved snippet may contain {host}, {seat} and {project}, which Saved snippets fills in from the terminal you open it for when you choose Insert or Review insert and run. {host} is the host name of the connection (a WSL connection uses its distro name and this computer says local), {seat} is the seat name of a seat terminal, and {project} is the last folder of the terminal's project path. The dialog shows the exact text that will be inserted before you choose Insert, and the saved snippet keeps the placeholders as you typed them. Any other text in braces is left alone, a placeholder written right after a dollar sign, such as ${host}, is left alone because shells use that form, and double braces such as {{host}} insert a literal {host}. A placeholder this terminal cannot fill, for example {seat} in a plain shell, is refused with a message and nothing is inserted, and a value with a line break or control characters is refused the same way. Values are inserted as they are, without shell quoting, so put quotes around a placeholder in the snippet when a name could hold spaces; the dialog warns when a value has spaces or shell characters. Insert still never presses Enter, and Review insert and run still shows the expanded text and needs its own click.

While a terminal has keyboard focus, Ctrl+Shift+K (Cmd+K on macOS) clears that terminal's scrollback and keeps focus in it, with the same effect as Terminal: Clear in the command center. Other terminals are unaffected. It only resets the local display: nothing is typed or sent to the shell or the seat, and the current prompt line and the content visible on screen stay. Plain Ctrl+K is not a clear shortcut. Ctrl+Shift+K and Cmd+K outside a terminal keep opening the command center, so on macOS Cmd+K clears only while a terminal has focus.

The terminal.copyOnSelect setting is off by default. When it is on, selecting text in a terminal copies exactly the selected text to the system clipboard about a quarter of a second after the selection stops changing. While the terminal Find bar is open nothing is copied, because Find selects each match. Clearing a selection never changes the clipboard, whitespace-only selections and selections longer than 20,000 characters (for example Select all on a large buffer) are not copied, and the same text is not copied twice in a row. A successful copy is silent and a failed one shows the usual terminal notice. It only writes to the clipboard: nothing is pasted or sent to the shell or the seat, and Ctrl+C, paste and the context-menu Copy behave as before. Selected text can include secrets shown on screen, so turn it on deliberately.

The terminal.confirmMultilinePaste setting is off by default, and with it off pasting works exactly as before. When it is on, pasting any text that contains a line break (CRLF, CR and LF alike) first shows "Paste N lines?" with the line count and a preview of the first 8 lines; extra lines and very long lines are cut off with an ellipsis, and text with no line break is never prompted. A single trailing newline is not counted as an extra line, so one command followed by Enter shows "Paste 1 line?", but it is still confirmed because a shell without bracketed paste would run it the moment it is pasted, and the dialog then adds the note "Ends with a line break: it will run immediately". Paste delivers the text exactly as copied through the terminal's normal paste, with no Enter added. Cancel, Escape, the close button and clicking outside the dialog paste nothing, and nothing is sent to the shell or the seat until you choose Paste. Keyboard focus starts on Cancel, so pressing Enter straight away does not paste. It covers Ctrl+V or Cmd+V, Ctrl+Shift+V on Windows and Linux, and the context-menu Paste; it does not apply to image paste, snippets or other programmatic inserts. The clipboard text is not logged or saved, and is kept only while the dialog is open.

Dropping a file from your computer onto a local terminal inserts its path at the prompt and never presses Enter. The path is quoted for the shell (single quotes for Bash, Zsh and PowerShell, double quotes for Command Prompt), several files go in as several quoted paths separated by spaces, and the text goes in through the terminal's normal paste, so nothing runs until you press Enter yourself. A short notice says how many paths were inserted, and a dashed outline marks a terminal that accepts the drop. Only local terminals accept it: dropping onto an SSH or WSL terminal inserts nothing and says "Dropped paths are local; remote upload is not supported", because a path on this computer means nothing on another host, and terminals that are not connected and OpenRig action terminals refuse too. A path that is empty, longer than 4,096 characters or holds a control, line-break or invisible character is refused with a notice and nothing is inserted, as is a drop of more than 20 files; Command Prompt also refuses a path with %, !, ^ or a double quote, because it would expand or misread it. A path with a line break is never inserted, so a dropped path never triggers the terminal.confirmMultilinePaste dialog. Dragging a panel tab is not affected, and there is no setting for this: nothing happens unless you drop a file from outside HRig. On a seat terminal the path goes in at the agent's prompt in the same way, and whether the agent reads a quoted path as a file reference depends on the agent. Uploading the file to a remote host is not implemented; docs/terminal-file-drop.md holds the design note.

The terminal.showSizeOnResize setting is on by default. After a terminal is resized, whether by dragging a panel divider, resizing the app window or changing the font size or zoom, a small readout of its size in columns and rows, for example "120 x 32", appears at the top center of the terminal for about 1.2 seconds, and the wait starts again if the size keeps changing. It is not shown when a terminal first opens or reconnects, or when the size did not change. Turning the setting off shows no readout. The readout is display only: it takes no focus or clicks, floats over the terminal so it never changes the terminal size, and sends nothing to the shell or the seat beyond the size update the terminal already sends. Screen readers hear it as a polite status message, and with reduced motion on it appears and disappears without a fade.

The terminal.cursorStyle setting chooses the cursor shape: bar (the default), block or underline. The terminal.cursorBlink setting is on by default and makes the cursor blink; turn it off for a steady cursor. Both are under Terminal in Settings and can be set for all projects or overridden for one project. A change applies at once to every open terminal, with no reconnect and no restart, and the shell or seat session is untouched: only how the cursor is drawn changes, and nothing is typed or sent beyond the size update the terminal already sends. While Reduce motion (appearance.reduceMotion) is on, the cursor does not blink even if terminal.cursorBlink is on, and blinking returns when Reduce motion is turned off, without changing terminal.cursorBlink.

The terminal.bellStyle setting chooses what a terminal bell does inside HRig: none (the default, which changes nothing) or visual. With visual, each time a program in a terminal rings the bell the terminal shows a highlighted outline for about 0.16 seconds, whether or not you are looking at that terminal. At most one flash is shown per second for each terminal however fast the bells arrive, and bells that arrive within three seconds of opening, reconnecting or restoring a terminal are ignored because they come from replayed history. The flash floats over the terminal, takes no focus or clicks, never changes the terminal size or moves anything, and nothing is typed or sent to the shell or the seat. HRig plays no sound. While Reduce motion (appearance.reduceMotion) is on, or the operating system asks for reduced motion, the outline does not fade: it appears and disappears at once. A desktop notification for a bell is a different setting, notifications.terminalBell (it needs notifications.desktop and applies only to a terminal you are not looking at); it is independent of terminal.bellStyle and both can be on at once.

The terminal.minimumContrastRatio setting keeps terminal text readable against its background. It is a number from 1 to 21 in steps of 0.5, and the default, 1, turns the adjustment off, so every color is drawn exactly as the program and the terminal theme set it. With a higher value, text whose color is closer to its background than that ratio is made lighter or darker until it reaches the ratio, which helps with dim ANSI colors such as dark blue on black; 4.5 is the WCAG AA level, 7 is AAA and 21 forces black on white or white on black. Only text colors are adjusted: background colors are never changed, and text that already meets the ratio keeps its color. The setting is under Terminal in Settings and can be set for all projects or overridden for one project. A change applies at once to every open terminal, with no reconnect and no restart, and the shell or seat session is untouched: only how text is drawn changes, and nothing is typed or sent beyond the size update the terminal already sends. Set it back to 1 to see the original colors.

The terminal.macOptionIsMeta setting is for macOS only and is off by default, which keeps today's behavior: the Option key types special characters, such as accents, as the keyboard layout defines. Turn it on to make Option act as the Meta key in terminals, so Option+B and Option+F move back and forward a word in shells such as zsh and bash with their default Emacs-style editing; while it is on, Option no longer types special characters in a terminal, including characters that some keyboard layouts type only with Option, such as @ and brackets on a German keyboard. On Windows and Linux the setting has no effect. It is under Terminal in Settings and can be set for all projects or overridden for one project. A change applies at once to every open terminal, with no reconnect and no restart, and the shell or seat session is untouched: only how your own Option key presses are encoded changes, and nothing is typed or sent unless you press a key. The terminal shortcuts for find, copy, paste and clear never use Option, so they behave the same either way. Turn the setting off again to get the Option characters back.

The terminal.wordSeparator setting chooses the characters that end a word when you double-click text in a terminal to select it. The default is xterm's own list: a space, parentheses, square and curly brackets, single and double quotes, a comma and a backtick, so nothing changes until you edit it, and a double-click selects everything between two of those characters, which keeps a path, a URL or key=value together. For example, set it to a space, a double quote and a single quote to make a double-click select foo(bar) or a,b whole, or add / and = to the default list to select one path segment or one side of key=value at a time. The value is plain text of up to 64 characters; line breaks and other control characters are not accepted, and it cannot be empty, because xterm treats empty text as its default, so empty never means no separators. Keep a space in the list unless you want a double-click to run across spaces. It is under Terminal in Settings and can be set for all projects or overridden for one project, and the reset button brings the default list back. A change applies at once to every open terminal, with no reconnect and no restart, and the next double-click uses it; the shell or seat session is untouched: only which text a double-click selects changes, and nothing is typed or sent. Triple-click still selects the whole line, and Find and link detection do not use this setting. Selected text is copied only when you copy it or terminal.copyOnSelect is on.

The terminal.copyTrimTrailingWhitespace setting is off by default, which keeps today's behavior: text you copy from a terminal is placed on the clipboard exactly as the terminal shows it, including the spaces and tabs that full-screen programs and padded output leave at the end of a line. Turn it on to remove the spaces and tabs at the end of every line of copied terminal text, so pasting it elsewhere does not carry invisible trailing blanks. It applies to every way of copying terminal text: the Copy button and Copy output in the terminal toolbar, the keyboard shortcut, Copy in the right-click menu, Copy in the Edit menu on macOS, and Copy on select when terminal.copyOnSelect is on. Only the end of each line changes: line breaks, leading spaces, blank lines and spaces inside a line are kept, and a selection made only of spaces and tabs is copied as it is. Leave it off when trailing blanks matter, such as a Markdown hard line break, which is two spaces at the end of a line. It is under Terminal in Settings and can be set for all projects or overridden for one project. A change applies at once to every open terminal, with no reconnect and no restart, and the shell or seat session is untouched: only the text placed on the clipboard changes, never what you paste into a terminal, and nothing is typed or sent. Exporting terminal output to a file is not changed.

While at least one terminal has ended or failed to attach, the command center lists "Terminal: Reconnect all dropped (N)" and the status bar shows a "Reconnect all dropped (N)" button, where N is the number of terminals it will reconnect. Both disappear when none are dropped. If the status bar is hidden by the appearance.statusBar setting, the command center entry remains. One click re-attaches every ended or errored terminal and shows "Reconnecting N terminals". Seat terminals re-attach to their existing seat session and no agent is launched or relaunched; plain shells start a fresh shell exactly as their own Reconnect does. It also ends any automatic retry countdown on those terminals and resets their retry budget. Terminals that are connected or still connecting, and one-time reviewed action terminals, are left alone. It runs only when you click it or press Enter on the command center entry, never automatically, and nothing is typed into any terminal. The terminal.autoReconnect setting behaves as before.

Start log opens a native file chooser on the desktop and appends future PTY output to that file. Logging is off by default, never restored from settings, and stops on disconnect, reconnect, terminal close or application exit. The visible Logging · Stop button ends recording and drains queued writes. Logs omit ANSI/OSC/DCS and control sequences (except tabs/newlines); cursor movements are not replayed, so full-screen/redrawing applications may produce repeated text. Existing files are appended, never truncated. Each log file is limited to 32 MiB and queued writes to 1 MiB; reaching either limit or a disk error stops logging with a visible message. Logs can contain secrets echoed by programs, even text later erased from the screen. Files remain until you remove them.

Mark view bookmarks the top visible normal-buffer line (up to 100 marks). Choose a mark to jump back; Clear marks removes them. Marks expire with scrollback trimming or terminal recreation and are not saved. Previous/Next error scans retained rendered rows for error, failed, fatal, exception or Traceback; this is a text heuristic, not a command-status detector. It does not wrap around or submit shell input.

Malformed control strings are discarded for at most 4,096 characters before plain logging resumes. Application shutdown allows up to four seconds to drain log writes; a stalled filesystem can therefore leave the final queued output unwritten.
