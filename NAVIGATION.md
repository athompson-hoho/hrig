# Project and panel navigation

Open a project with Ctrl+O (Cmd+O on macOS). The project hub lists attached rig folders, recent folders and favorites, with host and rig labels. Search, pin or remove history entries, browse a folder, or enter a path. Removing history never deletes files or rigs.

History retains up to 50 favorites and 50 recent projects. Entries are tied to the saved connection and endpoint; removed or retargeted connections appear unavailable. HRig validates a folder before switching and preserves the current project when validation fails or the dialog is canceled. Layouts remain associated with their existing project path. History stores folder/host metadata, not file contents or credentials.

Ctrl+P (Cmd+P) opens fuzzy project-file search. Type a filename or path subsequence, optionally followed by `:line`; use arrows and Enter to open a result. Local, WSL and SSH connections use the same ranking. Traversal is bounded to 20,000 entries and 25 levels, excludes generated directories and symbolic links, and returns the best 100 matches found. Partial and limited scans are explicitly labeled. Existing file confinement and size limits still apply. Superseded results are discarded; dismissing the dialog does not terminate an already-running remote read.

Ctrl+Shift+P (Cmd+Shift+P) finds existing panels in the current workspace by title, file, rig, seat, host or group. Recent panels appear first. Selecting a result focuses its docked panel, floating panel or native popout without opening another copy. The navigator also offers move-to-group and split controls, including Alt+Left/Right/Down/Enter. Rename groups in Arrange workspace; moves, splits and group names participate in arrangement undo.

Ctrl+Tab switches panels in most recently used order: it goes to the panel you used before the current one, and Ctrl+Shift+Tab goes the other way, to the panel you used longest ago. It is the Control key on macOS as well, not Cmd, which the system keeps for switching apps. Keep holding Control and press Tab again to go further back; the order is frozen while Control is held, so repeated presses walk down the list instead of flipping between two panels, and releasing Control makes the panel you stopped on the most recent. There is no overlay: the panel itself changes, as it does when you click its tab, and keyboard focus moves into it. A held Tab does not repeat, panels in a separate window are skipped, and the shortcut is ignored while a dialog is open. If a group is maximized and the next panel is in another group, the layout is restored first, as in the panel finder. The order is kept in memory for this session and is not saved, it is separate from the recent panels the panel finder lists first, and a closed panel leaves it. The shortcut is handled for the whole window, so in a terminal it replaces the plain Tab that Ctrl+Tab used to send, while Tab itself still reaches the shell; it is listed in the Keyboard shortcuts sheet and cannot be rebound there. Switching only selects a panel: nothing is typed or sent to a terminal or seat.

Right-click a panel's tab for Close, Close others and Close to the right. They work on only the panels in that tab's own group, never on other groups or windows: Close others closes every other tab of the group, Close to the right closes the tabs after it, and pinned tabs are skipped. An item is disabled when it has nothing to close. HRig closes the panels from right to left. More than one panel, or any terminal, asks first and says how many close: closing a shell ends it and what runs in it, while a seat panel only detaches and the seat's session keeps running. A panel with unsaved edits asks before it closes, one at a time, with the same Save, Discard and Cancel choices as its tab button; Cancel stops the run and leaves the rest open, and panels already closed stay closed. Nothing is discarded without an answer. Every panel closes the way its tab button closes it, so Reopen closed panel brings back files, diffs and seat panels you closed this way, newest first. Shells are not remembered, and only the last 10 closed are kept, so after closing more than 10 files and seats at once only the last 10 can be reopened. There is no keyboard shortcut for these actions, and nothing is typed or sent to a terminal or seat.

Project path spelling remains stable to preserve previous layout keys. Different aliases for the same remote folder can remain separate entries. Project text search in Project tools stays literal and case-insensitive by default; the .* and Word buttons add regular expression and whole-word matching and the Files button adds include and exclude globs, all bounded in pattern size, line length, files, matches and time. See docs/content-search.md for the syntax, the limits and the differences between local, WSL and SSH connections.

Seat rows and the command center offer Open seat beside current. This reuses an existing seat panel and puts it to the right of the active group. See [terminal splits](docs/terminal-splits.md) for behavior and existing arrange/navigator controls.

The command center (Ctrl+K, Cmd+K on macOS) also runs Toggle sidebar, Toggle status bar, Refresh rigs and workspace and Open welcome guide; Toggle status bar flips the appearance.statusBar setting, so the same entry turns it back on. Typing several words keeps only the commands whose name or hint contains every word, lists name matches before hint-only matches, and Enter runs the first command in that list. These commands only change what is shown or re-read data and none sends anything to a terminal or seat.

With an empty query, Quick Open lists the files you opened most recently in this project under Recent files, newest first; arrows and Enter reopen one, and typing switches to the normal search while clearing the query brings the recents back. HRig keeps up to 20 project-relative paths per project in the workspace file (paths only, never file contents), and forgets a path when opening it fails. The panel navigator likewise lists open panels most recently focused first while its query is empty. Choosing an entry only opens the file or focuses the panel and sends nothing to a terminal or seat.

The Welcome screen lists up to five of your pinned and most recently opened projects under Continue where you left off, pinned ones first and marked with a star; with no history the section is not shown. Click a project to open it exactly as the project hub does: the Open a project dialog appears while HRig checks the folder, closes once the project is open and stays up with the error if the check fails. An entry whose connection was removed or retargeted is shown as unavailable and cannot be opened. Opening a project only switches folders and sends nothing to a terminal or seat; pin, unpin and remove stay in the project hub.

Press ? when focus is not in a text field, the editor or a terminal to open the Keyboard shortcuts sheet, a list of the app, terminal and editor shortcuts with Cmd or Ctrl labels for your platform and the keys now in use; Escape, ? again while the search box is empty, or a click outside closes it. The command center entry Open keyboard shortcuts opens the same sheet, and the welcome guide and Settings point to it. The sheet sends nothing to a terminal or seat, and a ? typed into a field, the editor, a terminal or while a dialog is open is left alone.

The command center entry Reopen closed panel, or Ctrl+Shift+H (Cmd+Shift+H on macOS), reopens the file, diff or seat panel you closed most recently in the current workspace. HRig remembers up to 10 closed panels, in memory only, so they are forgotten when the app restarts. Each is kept as its kind plus the project, path or seat identifiers needed to open it again, never file contents, terminal output or commands, and closing the same panel twice keeps only the newest copy. A file or diff reopens exactly as if you had chosen it in Quick Open or the sidebar, so a deleted file shows the usual error and edits you discarded when closing are not restored. A seat reopens through Open seat, which attaches to the seat's existing session: it never launches, relaunches or restarts an agent, and nothing is typed or sent. Shells, rig-control terminals, settings and tool panels are not remembered, because closing a shell ends it and a reopen would start something new; Ctrl+Shift+T (Cmd+Shift+T) still opens a new shell. When the seat is gone or the connection has changed, a short message says why, and a seat that only needs a refresh stays in the list. With nothing to reopen the command shows Nothing to reopen. The shortcut is ignored while a dialog is open and does not repeat while held, and in a terminal it replaces Ctrl+Shift+H, which no longer reaches the shell.

Double-click the empty part of a panel group's tab strip, press Ctrl+Shift+M (Cmd+Shift+M on macOS), or choose Maximize panel in the command center to make that group fill the workspace. The other groups are hidden, not closed: their terminals keep running and every tab, size and arrangement is kept exactly as it was, so double-clicking the strip again, pressing the same shortcut or choosing Restore panel layout brings back the previous layout. Double-clicking a tab still renames it, and the maximize button in the group's toolbar works as before. Escape never restores, because editors and terminals need it. With only one group open there is nothing to hide, and a short message says so. Maximized is a view state for the current session and is not saved with the layout: after a restart, when you switch projects and come back, or when you apply a saved or role layout, every group is visible again. A new panel opens in the maximized group, a panel that is already open in a hidden group is only selected there until you restore the layout, and Find open panels restores the layout first when you pick a panel in a hidden group. The shortcut is ignored while a dialog is open and does not repeat while held, and in a terminal it replaces Ctrl+Shift+M, which no longer reaches the shell; plain Ctrl+M, including Monaco's Tab key moves focus toggle in the editor, is unchanged. Terminals in the visible group are refitted by the normal resize path and terminals in hidden groups are left alone; nothing is typed or sent.

Layout undo notice: after Arrange: Team, Focus or Review (from the command center, the Layout presets menu or the Arrange workspace panel, and also when the review workspace arranges Review as it opens a seat or a diff), Open all rig sessions, or applying a saved role template in Arrange workspace, the notice that confirms the change has an Undo button. One click puts the previous layout back, one step through the same history as the command center entry Undo arrangement and Redo arrangement, and closes the notice; Redo arrangement brings the new layout back. The notice stays for 8 seconds instead of 4.5, and the time stops while the pointer rests on it. The button is only offered when the panels really moved, and it goes away, leaving the plain notice, as soon as anything else has changed the layout since: another arrangement, a panel moved, split, resized or renamed, a panel opened or closed, or an Undo or Redo from elsewhere. So it can only undo the change it was shown for, and only once, and ignoring it changes nothing. Single moves, splits, group renames, equal sizes and maximize do not show it, restoring a saved layout from the Layout presets menu has no Undo, and there is no setting or shortcut for the button; the command center entry Undo arrangement is the keyboard route and works at any time, not only while the notice is up. The button only changes where panels are shown, the same step Undo arrangement takes: nothing is typed or sent to a terminal or seat.

Rename a terminal panel: right-click the tab of a shell or a seat panel and choose Rename... to give it a title of your own, for example Build logs. Type the title and press Enter to save it; Escape or Cancel leaves the name as it was. A title typed on the tab itself (double-click it, or press F2) follows the same rules. The title is cleaned: line breaks and runs of spaces become one space, control, zero-width and direction-override characters are removed, and it is cut at 60 characters. An empty title, or the original name, puts the original name back. Once a panel has its own title the same menu also offers Reset name, which puts the original name back; the original is saved with the panel, so this works after a restart too. The title is saved with the workspace and with saved layouts, and is cleaned again whenever a workspace, a saved layout or a role template is loaded. Only terminals are renamed this way: files, diffs and other panels keep their names. A title is only a label on the tab, in Find open panels and in the panel navigator: the terminal header still shows the seat name and host, the session, the seat and the panel id are not touched, and nothing is typed or sent to a terminal or seat. A seat panel that Reopen closed panel brings back starts with the seat's own name, and a role template gives a seat panel its seat name. A rename takes away the Undo button of the layout notice, and Undo arrangement puts back the titles the panels had in the earlier layout.

The command center entry Toggle focus mode, or Ctrl+Shift+D (Cmd+Shift+D on macOS), hides the sidebar and the status bar so the panels get the whole window, and running it again puts both back exactly as they were: a sidebar or status bar you had already closed stays closed. Focus mode is a view state for the current session only. It is not a setting, nothing is saved or written, and the Show status bar preference is never changed; the status bar returns when focus mode ends and follows whatever that preference says then, so choosing Toggle status bar while focus mode is on changes the saved preference and takes effect when you leave. Opening the sidebar by any route (Ctrl+B, Toggle sidebar, the sidebar button, an activity rail icon, opening a project) ends focus mode and keeps the sidebar open. The activity rail and toolbar stay visible, panels, terminals and the layout are not touched, and restarting the app starts with focus mode off. The shortcut is ignored while a dialog is open and does not repeat while held, and in a terminal it replaces Ctrl+Shift+D, which no longer reaches the shell; plain Ctrl+D, including Monaco's add selection to next match in the editor, is unchanged. Terminals refit through the normal resize path as the workspace area changes, and nothing is typed or sent.

The sidebar shows and hides with Ctrl+B (Cmd+B on macOS), with the Toggle sidebar entry in the command center, or with the Hide sidebar and Show sidebar button in the toolbar; the shortcut is also listed in the Keyboard shortcuts sheet. It is handled for the whole window, including while a terminal has focus, so Ctrl+B does not reach the shell or a program such as tmux. Drag the thin handle on the right edge of the sidebar to resize it between 210 and 440 pixels. HRig saves the width with the workspace and restores it at the next start: a saved width outside that range is moved to the nearest limit, a saved value that is not a number falls back to the default of 264 pixels, and a new workspace starts at 264 pixels, as it always has. Hiding the sidebar keeps its width, so showing it again, with Ctrl+B or by leaving focus mode, brings it back at the same size. Whether the sidebar is open is not saved: it is open at every start. The width is not a setting, and nothing is typed or sent.

Ctrl+G opens the go-to-line prompt in the code editor, in a diff view too, while that editor has focus (Control+G on macOS, where Cmd+G finds the next match); the shortcut is listed in the Keyboard shortcuts sheet. The command center entry Go to line opens the same prompt in the editor that had focus when you opened the command center, and shows Click an editor first when none did. Type a line number, optionally followed by a colon and a column such as 12:5 (a comma or # also separates them); a negative number counts from the end of the file, a number past the end goes to the last line, Enter jumps and Escape cancels. The shortcut belongs to the editor only, so in a terminal Ctrl+G stays the shell's own key and a text field keeps it. It is separate from the :line suffix in Quick Open, which opens a file at a line. The prompt is the editor's own: there is no setting, nothing is saved, and nothing is typed or sent.

Shortcut overrides: three shortcuts can be given other keys from the Keyboard shortcuts sheet: Reopen closed panel, Maximize panel and Toggle focus mode. Type in the search box to filter the list by words in a name or its keys. A row with an Edit button takes typed keys such as Ctrl+Shift+Y (Ctrl and Cmd both mean the main modifier of your computer, Shift is required and the key is one letter A to Z), and Save checks them before anything is stored: keys that a terminal uses (Shift with F, C, V or K), that the code editor uses (Shift with A, G, I, K, L, O, R or Z), that another shortcut uses, or that are not Shift and one letter are refused with the reason and nothing changes. Reset puts one shortcut back and Reset all removes every change, so the defaults always return. The sheet and the command center hints then show the keys now in use, the old keys of a moved shortcut stop running it and reach the terminal again, and with no changes saved every key, label and hint is exactly what it was. Every other shortcut in the list is fixed, because its key handling is not routed through the shared check and a wrong rebinding could take a key from a shell or the editor: the command center, Quick Open, the panel finder, settings, project, sidebar, new shell and help keys and every terminal and editor key. This is a typed text field and not a key recorder, and nothing is typed or sent to a terminal or seat. The changes are the shortcuts.overrides text setting described in SETTINGS.md, so Settings under Workspace shows the same text. See docs/shortcut-rebinding.md for what rebinding the fixed shortcuts would need.

Task board keyboard navigation: in the Task queue panel the board is one Tab stop, on the card you used last, and the arrow keys then move between cards: Up and Down inside a column, Left and Right to the nearest column that has cards, Home and End to the first and last card of the column. Enter or Space opens the task details, as a click does, and Escape closes them. The keys act only while a card has focus and only without Ctrl, Alt, Cmd or Shift, so the filter boxes, the app shortcuts and terminals keep every key they had. It is not a global shortcut: it is not in the Keyboard shortcuts sheet or the command center, it cannot be rebound, there is no setting for it, and nothing is typed or sent to a terminal or seat. TASKS.md describes what the board does when it refreshes.

Window title: with Show project and panel in the window title turned on in Settings (Appearance, off by default), the main window is titled with the name of the panel you are in, the name of the project folder and hRig, for example Build logs - hrig - hRig. The title follows your tab and project changes, and a renamed panel shows its new name; a part that is missing is left out, and with the setting off the title stays hRig. HRig draws its own title bar, so this text shows in the taskbar, the window switcher and the window list; the title bar inside HRig does not change, and detached windows keep hRig. The text is cleaned (control, zero-width and direction characters are dropped), the panel name is cut to 50 characters and the project name to 40 around an ellipsis, the whole title never has more than 100 characters, and the main process checks it again and always ends it with hRig. Only those two names are used: never file text, seat output, a host name or a secret.
