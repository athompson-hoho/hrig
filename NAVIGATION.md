# Project and panel navigation

Open a project with Ctrl+O (Cmd+O on macOS). The project hub lists attached rig folders, recent folders and favorites, with host and rig labels. Search, pin or remove history entries, browse a folder, or enter a path. Removing history never deletes files or rigs.

History retains up to 50 favorites and 50 recent projects. Entries are tied to the saved connection and endpoint; removed or retargeted connections appear unavailable. HRig validates a folder before switching and preserves the current project when validation fails or the dialog is canceled. Layouts remain associated with their existing project path. History stores folder/host metadata, not file contents or credentials.

Ctrl+P (Cmd+P) opens fuzzy project-file search. Type a filename or path subsequence, optionally followed by `:line`; use arrows and Enter to open a result. Local, WSL and SSH connections use the same ranking. Traversal is bounded to 20,000 entries and 25 levels, excludes generated directories and symbolic links, and returns the best 100 matches found. Partial and limited scans are explicitly labeled. Existing file confinement and size limits still apply. Superseded results are discarded; dismissing the dialog does not terminate an already-running remote read.

Ctrl+Shift+P (Cmd+Shift+P) finds existing panels in the current workspace by title, file, rig, seat, host or group. Recent panels appear first. Selecting a result focuses its docked panel, floating panel or native popout without opening another copy. The navigator also offers move-to-group and split controls, including Alt+Left/Right/Down/Enter. Rename groups in Arrange workspace; moves, splits and group names participate in arrangement undo.

Project path spelling remains stable to preserve previous layout keys. Different aliases for the same remote folder can remain separate entries. Existing content search remains literal; regex, whole-word and include/exclude content filters are future HR-16 work.

Seat rows and the command center offer Open seat beside current. This reuses an existing seat panel and puts it to the right of the active group. See [terminal splits](docs/terminal-splits.md) for behavior and existing arrange/navigator controls.

Open Connection doctor from Workspace tools or the command center. Select Export redacted diagnostics… to choose a local JSON destination in the native Save dialog (suggested name: `hrig-diagnostics.json`). Choose a new file name; existing files are not replaced. While saving, the action shows Exporting… and is disabled against repeat activation. Diagnostics saved. means publication completed. Canceling reports Export canceled. No file was saved. A write failure, existing destination or unsupported filesystem shows Could not save diagnostics. The destination may already exist, or the filesystem may not support this export. Try a new file name on a supported, writable filesystem. The action becomes available for an explicit retry; no path or raw error appears in the export notice. Each later export requires another explicit activation and a new destination.

Export uses the eligible represented check-status snapshot at activation; it does not run checks or certify the host's current health. Its logs contain statuses for eight fixed known check labels, with missing, invalid or duplicate entries marked unknown. When the report is absent, checking, failed, obsolete, malformed or oversized, check statuses are unavailable and local versions/settings remain exportable. Opening Doctor and selecting Run checks retain their separate existing diagnosis effects; running checks is not required to export.

The bounded bundle includes recognized numeric local HRig/Electron/Chromium/Node.js versions and nine validated effective settings: appearance density/reduced motion, editor font size/tab size/word wrap, terminal font size/cursor style/scrollback, and workspace refresh interval. Invalid settings are omitted and unrecognized versions are unavailable. It excludes raw/historical application or host logs, check details, terminal text, private identities, credentials, environment/workspace history and free-form settings. Export adds no collection, polling, upload, terminal input or agent lifecycle action. See [redacted diagnostics privacy and file limits](PRIVACY.md#redacted-diagnostics-export).

Native Save/cancel/focus, keyboard and assistive-technology announcements, themes/density and reflow at 320px/200% text, actual filesystem permissions/hard-link support and crash durability remain human-needed until observed with authorized disposable data. Owner confirmation that status-only logs meet the intended diagnostic usefulness also remains pending; automated checks do not supply that judgment.

Attention center shows a Needs input inbox for its captured connection and represented inventory. It includes every row whose normalized status is exactly `attention`, in inventory order, including duplicate represented rows. The count includes those rows only. Sidebar rig selection, search, status, sort, pins and collapsed pods do not hide or reorder the inbox. It does not query every saved host. Each row identifies the seat, rig, pod, connection and represented session; missing context is labeled unavailable.

With verified matching inventory, Needs input (0) means no represented seats need input. Loading or unavailable inventory does not claim zero. Owned stale or checking snapshots retain their rows with a Last known needs input count and an explanation; Jump is disabled until inventory is verified without a reported error. Foreign inventory is withheld. An ordinary background poll alone does not invalidate an otherwise verified healthy snapshot. A represented seat without an attachable session stays visible with an explanation.

Activate Jump to seat explicitly to open the current represented target or focus its exact existing panel. Before navigation, HRig checks the latest captured/current connection identity (id, kind, host, port, distro and rig binary), inventory ownership and health, seat/rig/status/session, current layout target and current actions. Renaming a connection or changing its project root alone does not change ownership. Removed, changed, ambiguous or obsolete targets refuse visibly. Existing docked, popout or detached targets must have matching terminal configuration and an available focus surface.

Terminal attachment reuses an exact matching retained owner, seat and requested session without requiring inventory. With no retained PTY, one unique current inventory match may refresh only the requested session for a single attachment; ambiguous matches refuse. Retained ownership is checked again after the inventory lookup. Unknown or conflicting retained ownership/session refuses reuse and preserves the existing terminal and session. Inspect its connection/session with the existing connection controls and OpenRig readiness information before trying again. Jump does not automatically switch connections, close, reset, replace or relaunch an existing owner terminal, submit terminal input, answer a prompt or refresh inventory.

Seat problems lists failed seats with reported errors separately and retains its guarded Open seat action. Blocked work retains its existing captured-connection queue loading, error and empty states; tasks never inflate the needs-input seat count. The existing Windows notifications checkbox keeps its existing preference behavior. Inbox loading or discovery does not enable notifications or add a notification feature, refresh action or polling loop.

Native Tab/Shift+Tab, Enter/Space activation, focus-visible and disabled explanations, docked/popout/detached window focus, narrow/wide long-label layouts, scrolling density, themes and authorized live attachment/refusal remain human-needed until directly observed. These checks must preserve existing owner PTYs and sessions. Earlier R01–R05 human verification gates remain open.

Filter sessions narrows the sidebar immediately by seat name, rig name, runtime, pod, model or session metadata in the selected rig (or All rigs). Matching is literal and case-insensitive, with surrounding query whitespace ignored. Clear the input, or enter only whitespace, to restore that rig's represented seats matching the still-selected status, in the selected sort order.

The status control offers All statuses, Working, Idle, Needs input and Stopped. Working includes normalized working and running; Idle and Needs input match idle and attention respectively; Stopped includes stopped/exited/failed. All statuses includes running, unknown and other unclassified or missing statuses. Status intersects with the current text query and selected rig: changing status, including returning to All statuses, preserves both; clearing the query leaves status active. All statuses is the initial/reset status, and both filter values live only in the mounted sidebar component, without storage or network requests.

Sort sessions orders those matched rows after the rig, query and status filters. Name is the default: natural, case-insensitive name ordering using English collation (`Intl.Collator("en", { numeric: true, sensitivity: "base" })`), so seat2 precedes seat10. Case/accent-equivalent names retain their source order. Activity (working first) orders exact normalized statuses as working, running, attention, idle, stopped/exited/failed together, then unknown or unclassified (including missing) statuses; each rank uses Name order. Activity is current status priority, with no timestamp or recency meaning. Attention first puts only exact attention statuses ahead of all other rows, with Name order within both groups; missing sessions or activity prose do not imply attention.

Changing sort preserves the query, status and selected rig, and only reorders represented rows. The choice uses the saved `rig.seatSort` preference; see [settings scope and persistence](SETTINGS.md#scope-and-persistence).

Each represented session has a separate pin button named `Pin session {seat name} in {rig name}`. Pinning changes it to `Unpin session {seat name} in {rig name}` with a pressed, filled pin icon. Matching pinned rows appear globally first after the selected sort and stay visible when their pod is collapsed. Remaining matches form pod groups in first-appearance order, retaining the selected sort within each group. Unpinning returns a row to its pod, subject to that pod's saved visibility. Pins respect the rig, query and status filters and never add missing rows or change the session count.

Pins belong to the exact saved connection identity (id, kind, host, port, distro and rig binary) plus the opaque `Seat.id`, which already contains rig and logical seat identity. Equal visible names in different rigs remain independent. Duplicate normalized IDs within the same connection share membership while retaining every represented row. Renaming a connection or changing its project root retains pins; changing any identity slot isolates them, including an absent port versus an explicit port. Temporary inventory absence retains the saved identity so a returning seat can appear pinned again.

App workspace state owns the identity-only `pinnedSeats` collection through its existing workspace save/load and shutdown flush. Legacy or malformed saved collections safely normalize; valid entries in mixed collections survive and duplicates collapse. This collection is separate from the sort preference. A workspace-save error remains visible and means durability is unconfirmed. Native keyboard/focus, theme contrast, narrow layout and survival across a real application restart require independent observation; element and serialization tests do not establish them.

Pinning is reversible local curation. It never opens, drags, relaunches, refreshes or sends input to a seat, and a pin does not indicate health, freshness or selection. Represented stale/checking rows can be pinned when their inventory belongs to the current connection; a connection transition with mismatched inventory ownership disables pin changes. Existing host-action guards continue to apply.

Pod groups start expanded. Activate the native `Collapse pod {pod} in rig {rig}` header to hide its matching unpinned rows, then `Expand pod {pod} in rig {rig}` to restore them. Favorites stay visible outside every controlled group. Only groups with matching unpinned rows have headers; all-pinned results have none. Collapsing every ordinary group retains headers and counts, without showing a false no-match message. Collapsed headers also show an attention dot and an accessible need-input count from their current matching unpinned rows only; filtered-out seats and favorites do not inflate this cue. Each header counts matching unpinned sessions; SESSIONS counts every match, including favorites and rows in collapsed pods.

Grouping follows rig, query and status filtering and the selected sort. Ordinary A/pod1, B/pod2, C/pod1 becomes pod1[A,C], pod2[B]; group adjacency changes while membership and within-group order remain. Collapse choices do not reset filters or expose filtered-out favorites.

Choices belong to the exact raw connection identity (id, kind, host, port, distro and rig binary), a tagged exact rig ID (or exact rig name when the ID is absent), and exact represented pod text. Case, punctuation and whitespace remain significant. Connection name/root changes retain choices; changing any identity slot isolates them. Missing pod metadata displays Ungrouped but differs from a literal pod named Ungrouped. Missing rig names display the represented ID or Unknown rig. Name fallback can only distinguish the identity represented by inventory; no stronger backend identity is inferred. Choices survive temporary absence, filtering and all-pinned groups without adding phantom headers.

App alone owns optional `collapsedPods` workspace membership. Absent or malformed data defaults safely expanded; valid mixed entries survive normalization. Existing full-workspace boot, 350ms save and latest-state shutdown flush carry choices alongside unrelated fields. Save failures retain the existing visible error and leave durability unconfirmed. Owned stale/checking inventory permits local disclosure; foreign-owner snapshots show groups expanded with disabled headers, and guarded callbacks reject obsolete connection choices. Collapse/expand never opens a seat, sends input, relaunches, refreshes inventory or starts network/timer work; existing host-action guards remain independent.

Native Enter/Space, Tab/Shift+Tab, focus retention, hidden-action exclusion, long-label clipping, bounded scrolling and themes at 210/264/440px remain pending actual desktop observation. Survival across a fully closed and newly launched process using the same disposable isolated profile also remains pending; serialization tests do not prove restart durability.

No matching sessions means active filters excluded available seats in the selected scope; an empty inventory retains its connection guidance. Filtering, sorting and disclosure preserve stale-inventory notices and disabled actions; opening, dragging or relaunching a seat still requires an explicit action.

All these lists use measured scrollable windows labeled Rig list, Sessions, Rig topology and Project search results. TaskBoard has separate Pending tasks, In-progress tasks, Blocked tasks and Other-state tasks windows. Short lists stay compact because their content is measured. Windows render visible rows with a small overscan; mounted rows are measured with their spacing so wrapped content keeps its measured height. A focused or dragged row can remain mounted outside the visible window until focus or drag leaves it.

The session container scrolls notices and empty guidance, including long stale errors and Retry connection. Non-list content does not shrink away; the inner session window has a usable minimum of two estimated rows and grows into available constrained space. Each mounted ordinary pod has one labelled pod-content group containing only its globally windowed rows, with stable parents across sparse retained gaps. Favorites and disclosure headers remain outside those groups. Optional aria-controls is omitted; each mounted disclosure description resolves to real unique content. These source contracts do not establish native scrolling reachability or assistive-technology announcement behavior.

TaskBoard title, owner and state filter changes intentionally remount each column viewport and reset its scroll to the start of the new filtered collection. This includes each title-filter keystroke. Complete filtered column counts and explicit task inspection retain their existing behavior.

Focus the list itself to use Arrow Up/Down, Page Up/Down, Home or End to reach row actions, including offscreen rows. These keys move focus without activating an action. Within a row, Tab and Shift+Tab follow its enabled native controls; at an unmounted row boundary they bring the next or previous row into view. At the actual list ends, Tab and Shift+Tab can leave the list. Use Enter or Space on the focused button to activate it. Session controls retain their order: open session, pin or unpin, open beside current, then relaunch where available. Rig topology retains rig selection and Delete review before that rig's seat buttons. Selecting a search result opens its captured path and line; selecting a task explicitly loads that task's details.

Windowing follows the full inventory composition: selected rig, session query and status, sort, favorites and pod disclosure. It applies across the session list and rig topology, including large groups. All rigs counts the represented rigs; SESSIONS counts all matching sessions, including favorites and sessions hidden by collapsed pods. Pod counts and collapsed needs-input cues still describe the full matching unpinned group. Task column counts describe every currently filtered item in that column, including offscreen cards. Scrolling does not change these counts or make a stale snapshot fresh; the independent Needs input inbox retains its existing scope.

Project text search retains its limit of 200 matches across 20,000 files. TaskBoard retains the latest 1,000 active queue items and applies its title, owner and state filters within that collection. Windowing adds no pagination or collection request. Browser Find can only find text currently mounted in these windows, so it cannot reliably search offscreen rows. Use Filter sessions, Project text search or the task filters to narrow the represented collection, then scroll or use the list's keyboard navigation.

Scrolling, resizing, focusing and moving between rows do not open a seat or file, inspect a task, refresh inventory, send terminal input or perform a lifecycle action. Existing explicit actions, disabled states and ownership guards remain in effect. Actual desktop scrolling, Tab order, focus retention, assistive-technology announcements, docking drag, themes/density and wrapping at 320px/200% text remain unobserved; no speed or FPS measurement is claimed. Earlier native, restart and owner-judgment gates remain pending.
