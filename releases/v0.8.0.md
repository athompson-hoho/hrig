# HRig 0.8.0 - Recovery, durable drafts and project boards

This release delivers the approved reliability priorities HR-11, HR-12 and HR-17, and adds local project boards, GitHub Issues/Projects and Linear integration. OpenRig continues to own agents, tasks and coordination.

## Changes

- Connection Doctor stops showing loading after a failed request. Last successful inventory remains visible with a stale label/timestamp; stale seat actions and recipients are unavailable until a successful refresh. Connection cache keys include the endpoint, preventing a previous host's snapshot from being reused for a different endpoint.
- Unsaved files have bounded, atomic local recovery copies. Startup highlights available copies; restored tabs display disk content until you choose restore or discard. Restoring never writes the project file. Revision checks continue to reject conflicting saves. Save All handles all known dirty buffers and preserves failed/conflicting drafts.
- Message drafts and accepted history persist per endpoint/project/rig/seat. Review drafts persist with recipient identity and file revision on each added note; stale notes are blocked before delivery. Interrupted sends preserve drafts with uncertain outcomes and never replay automatically. Accepted by OpenRig does not mean read by an agent.
- Saved drafts management offers explicit deletion and clearing while preserving local board records. Draft content may contain sensitive text and is stored locally as plaintext outside project files/settings exports.
- Project boards support local task creation/edit/delete and Todo/Doing/Done transitions. GitHub Issues supports read, create and open/closed changes using the existing Windows GitHub CLI login. GitHub Projects displays status columns and cards. Linear supports encrypted personal-key storage, team/project selection, issue creation and workflow-state changes.
- Every external mutation and OpenRig assignment requires a deliberate confirmation. Assignments include a source link and record the actual returned task identity. No agent is launched or source status silently synchronized. Fixed provider endpoints, argv/stdin transport, bounded responses, credential redaction and no automatic mutation retries constrain the integration boundary.

## Validation

Production build, all 20 backend checks, all 25 Electron journeys, mobile build/browser journey, development smoke and packaged Windows smoke passed. The packaged check also verified local boards, draft IPC and a real Windows encryption roundtrip. Dependency audit reported zero vulnerabilities. A real authenticated GitHub repository read passed. The packaged board screenshot was visually reviewed. New tests exercise draft persistence/limits/corruption, provider permissions/confirmation guards, encrypted-key handling, abrupt exit/recovery, disk conflicts, stale inventory, uncertain messages, review recipient/revision protection and local/provider boards. Provider writes use fixtures; no real issue or live rig was mutated for QA.

## Known limitations

GitHub Projects is read-only; this release does not reorder cards or modify arbitrary project fields. Lists are bounded to 100 items and disclose partial results. GitHub.com and Windows GitHub CLI login are supported; Enterprise hosts and OAuth-based Linear sign-in are follow-ups. A Linear personal key and provider permissions must be configured by the user. Live Linear writes/private Projects permissions require deployment validation. OpenRig assignment is an explicit linked task, not bidirectional synchronization. Local recovery is not a backup service; shared storage is bounded to 100 records/20 MB. SSH tunnels, real mobile devices and Windows assistive workflows retain the previously documented deployment checks.

## Install or upgrade

Download the Windows portable executable from this release. Close HRig normally before replacing or moving executables; do not replace files in a running unpacked application. Existing settings, layouts and project files remain in place. Saved recovery/message/review data lives separately in HRig's user-data folder. See RECOVERY.md and INTEGRATIONS.md for controls, storage and setup.

## Integrity and source

The release includes a SHA256SUMS file alongside the portable executable. Compare the executable's SHA-256 with that file before running it. The v0.8.0 tag identifies the source used for this build. Full release notes and upstream community-theme licenses are retained. No credentials, real project files, or user terminal output are included in screenshots or test fixtures.
