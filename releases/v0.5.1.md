# HRig 0.5.1 - Git folder error handling

## Fixed

Opening Source control or Review while the project root was a non-repository directory could surface a Python CalledProcessError traceback. A home directory selected as the project triggered the reported issue.

- Git status now returns a structured non-repository state.
- Source control and Review offer a Choose project folder action instead of an error or misleading clean working tree.
- Genuine Git failures retain useful Git stderr, including corrupt repository metadata, rather than a Python wrapper traceback.
- The fix does not initialize a repository in the home directory or change Git trust settings.

## Validation

Production build, eleven core/WSL checks, fourteen desktop journeys, and packaged native-terminal/editor/doctor/Git smoke test passed. Regression coverage includes local and WSL non-repositories, corrupt Git metadata, and choosing a valid repository after opening a non-repository folder.

## Known limitations

Project selection still uses manual path entry for remote folders in this version; one-click live rig folders arrive in v0.5.2. Other v0.5.0 limitations remain.

## Install or upgrade

Download **HRig.0.5.1.exe** from this release's assets on Windows x64. Close the running HRig instance before opening the new portable executable; existing user settings remain in the HRig application-data directory. WSL or SSH hosts need Linux Node, OpenRig, tmux, and Python 3. Connect the host in HRig; this application does not install an agent harness for you.

The executable is unsigned. Windows may show a publisher warning. Only run files obtained from this repository.

## Integrity and source

The attached **HRig-0.5.1-SHA256SUMS.txt** contains the SHA-256 digest of the executable. Check it with PowerShell: Get-FileHash -Algorithm SHA256 -LiteralPath './HRig.0.5.1.exe'. The executable is a release asset, not part of the Git source archive.
