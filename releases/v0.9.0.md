# HRig 0.9.0 - Installed desktop foundation and update safeguards

This release keeps Electron and improves installation, update safety and architectural boundaries. It retains the OpenRig workspace, community themes, recovery/drafts and project integrations from 0.8.x.

## Changes

- Windows now includes an assisted per-user installer with directory choice, Start Menu/Desktop shortcuts and uninstall support. The portable EXE remains a separate download. Application data is preserved on uninstall.
- Linux gains DEB and RPM packages on both x64 and ARM64 alongside AppImage and tar.gz. macOS keeps native Apple Silicon/Intel DMG and ZIP downloads.
- Added Settings > Updates with explicit stable-version checks, release notes, release-download links, signed-build download progress and a separate restart confirmation. No update is downloaded at startup or installed merely because the app quits.
- Signed in-app installation requires a generated signing policy and a pre-install workspace handshake. Unsaved editor buffers or failed workspace persistence reject installation before an installer can be spawned. The workspace becomes inert only after it is safe to restart, and errors restore interactivity. Updates never restart OpenRig agents.
- Unsigned, portable, development and Linux builds use the manual release/package-manager path. Architecture-specific feeds prevent Intel/ARM metadata collisions. Release publication checks feed hashes, package manifests and configured signatures.
- Prepared Apple Developer ID/notarization and Windows Authenticode CI secrets and validation. Partial signing configuration fails closed; credentials were intentionally deferred by the user, so this release does not claim signing/notarization or enabled automatic installation.
- Added an Electron-independent application-service facade and separated update policy/state from the host adapter. Added reproducible fresh-process benchmarks for 0, 12 and 24 disposable terminal panels, editor/settings responsiveness, working sets and idle CPU.

## Validation

Publication is gated on all five native OS/CPU targets passing backend contracts, production build, feed/package verification, packaged runtime checks and performance capture. Windows additionally installs, launches and uninstalls the actual installer on a disposable runner and verifies application data survives. Update tests cover manual/unsigned refusal, signature/network failures, no automatic install-on-quit, confirmation and unsaved-work rejection. Renderer tests exercise the actual restart handshake without executing a real updater. Configured code signing is validated only when real credentials exist; it is not asserted from unit mocks.

The attached NATIVE-QA.json contains native runtime/distribution evidence and performance reports. Measurements are baselines, not performance promises: a shared OS cache, virtualized hardware and external shell/agent memory are explicitly accounted for. No live rig was mutated for QA.

## Known limitations

Apple and Windows signing credentials are not configured. macOS remains unsigned and unnotarized; the current builds provide manual update checks/download links while signed in-app installation stays disabled. Signing support is prepared for a future credential-backed release. Linux package repositories/GPG signing and automatic package-manager updates are not configured. DEB/RPM package metadata and the shared application runtime are tested; this does not establish installation behavior on every Linux distribution or desktop environment.

The benchmark uses local shell fixtures, not live LLM agents, and sums Electron process working sets rather than total system memory. Native permissions, Windows notifications, real remote SSH endpoints and Wayland/keyring variations retain deployment checks. Existing GitHub Projects integration remains read-only, and external issue changes/assignments require deliberate actions.

## Install or upgrade

On Windows choose the setup EXE for installation and shortcuts, or the portable EXE for manual use. On macOS choose the correct CPU's DMG/ZIP and copy HRig to Applications; review system security prompts for this unsigned build. On Linux use the appropriate DEB/RPM package for your distribution, or AppImage/tar.gz. Do not mix architectures. Close HRig normally before replacing application files.

Existing workspace/settings/drafts remain in the OS application-data folder; local paths and encrypted credentials are machine-specific. Updates > Open release downloads provides the manual path while signing credentials are pending. See DISTRIBUTION.md for signing setup, update policy and installer behavior.

## Integrity and source

The v0.9.0 tag identifies the validated application source. SHA256SUMS covers the published distributions, feeds and blockmaps; the publisher checks GitHub asset digests before publication. NATIVE-QA.json records matching source and all five native targets. The Windows installer, Linux packages and architecture-specific update metadata are published together with these full notes. Previous release tags/assets are not overwritten.
