# HRig 0.13.0 - Rig bypass and plan-aware teams

## New

- Add an unchecked-by-default YOLO / bypass permissions option to the rig wizard. It saves OpenRig permission_policy: builtin:yolo and uses advertised --non-interruptive support for first-launch notices.
- Review displays the permission mode. Changing bypass requires a fresh preview; the backend binds launch permission policy to the exact previewed design and still requires typed launch confirmation.
- Read Codex plan labels through a bounded, read-only app-server account/read request with refreshToken:false. Read Claude subscription labels from auth status. No model turn or login is started by plan discovery, and credentials/raw account responses are not persisted.
- Add editable, project-scoped monthly plan amounts in the wizard and Settings. The initial Claude $200 and Codex $100 values reflect operator-provided information, not inferred billing prices.
- Auto weights authenticated runtimes by those declared amounts. Claude leads for the $200/$100 setup, while Codex remains available for independent review. A four-seat template uses three Claude seats and one Codex seat; single-runtime overrides and protected manual edits remain authoritative.
- Pass account-plan evidence and operator-declared amounts into AI team assessments, and prefer the higher configured amount for the initial assessment-provider selection when both are authenticated.
- Preserve intentionally moved focus when dismissing a dialog instead of restoring focus over a navigation destination.

## Validation

All 67 applicable backend checks passed (one platform-specific skip), covering plan allocation, malformed inputs, read-only account RPCs, cleanup, preview policy binding and permission-toggle recovery. Read-only checks on Windows and Ubuntu WSL reported Claude Max and Codex Pro Lite. Installed OpenRig's policy resolver reported builtin:yolo with launch_posture=full_bypass on a disposable generated spec. No live agents were launched or modified for that check. All 33 desktop regression journeys passed, including plan priorities, YOLO selection and the updated wizard. Wizard screenshots and packaged runtime/feed/installer checks gate publication; attached native QA records the source and build evidence.

## Known limitations

Plan labels depend on provider/version support and may be unavailable. Monthly cost is not a measure of remaining quota, model capability, context usage or guaranteed concurrency. Adjust the configured amounts when changing accounts; current checks describe the selected host CLI identity, not arbitrary Orca-managed or per-seat account overrides. Existing manually selected runtimes are not silently reassigned.

Bypass broadens native agent permissions for the generated rig. It does not override enterprise/runtime restrictions, change existing seats, or replace separate launch confirmation. Older OpenRig versions that do not advertise the required flag produce an error. Native policy resolution is verified; this does not claim a real model session executed unrestricted commands.

SignPath Foundation application submission is maintainer-confirmed; approval and signing integration remain pending. Downloads remain unsigned, macOS is not notarized, and Windows in-app installation requires acknowledgment of the unsigned update.

## Install or upgrade

From HRig 0.12.0 on Windows, use Settings > Updates or the new-version prompt to download, verify and install after confirming restart. Unsaved editor changes block restart. Older versions need one manual upgrade. Portable Windows uses per-user setup; unsigned macOS and Linux retain download/package-manager paths. Native downloads include Windows setup/portable, macOS DMG/ZIP and Linux AppImage/archive/DEB/RPM for their listed architectures.
