# HRig 0.8.1 - Native macOS, Linux and Windows releases

HRig now ships native desktop downloads for Apple Silicon and Intel Macs, x64 and ARM64 Linux, and x64 Windows. This release retains the recovery, message/review drafts, project boards, community themes, GitHub and Linear features introduced in 0.8.0.

## Changes

- macOS: separate arm64 and x64 DMG and ZIP downloads, system login-shell terminals, native OpenSSH, a standard application/edit/window menu, and local OpenRig discovery/attachment.
- Linux: separate x64 and arm64 AppImage and tar.gz downloads, system login-shell terminals, native OpenSSH and local OpenRig discovery/attachment. Choose Bash or Zsh explicitly in settings, or leave System default.
- Windows: keeps PowerShell/Command Prompt, WSL and Windows OpenSSH. New local shells use a platform-aware System default while existing explicit preferences remain supported.
- Removed Windows-only executable assumptions from SSH forwarding and terminal startup. Unix GUI launches include standard Homebrew and user-local executable locations in their process environment without editing shell profiles.
- Linear credentials use host secure storage. Linux's plaintext `basic_text` fallback is refused; enable the desktop secret service/keyring before connecting Linear. Local drafts remain local plaintext as documented in RECOVERY.md.
- Native packaging rebuilds the terminal module for the host OS/CPU. A manual GitHub Actions release matrix validates five native targets before publishing a complete set of downloads, checksums and machine-readable smoke evidence.

## Validation

Publication is gated on each native runner passing the available unit/transport tests, TypeScript/production build, native dependency packaging and packaged smoke checks. The packaged checks exercise a real PTY command, Monaco file loading, file save/stale-save rejection, non-repository Git behavior, Doctor, fixture-only native OpenRig inventory, local board creation and persistence, and draft persistence across restart. The release includes NATIVE-QA.json with the actual host architecture and results for all five targets. WSL-dependent tests are skipped on hosts without WSL; the Windows development regression suite is recorded separately in ROADMAP.md.

No live rig was started, stopped, deleted or messaged for release QA. Native inventory checks use a temporary executable fixture and isolated application data. Smoke tests do not require the user's GitHub or Linear credentials.

## Known limitations

macOS applications are unsigned and not notarized: an Apple Developer signing identity was not configured for this release. macOS may block first launch; review the source/checksum and use the system's Privacy & Security approval only if you trust this build. This release does not claim App Store distribution. Linux is built/tested on Ubuntu 24.04-family runners; desktop keyrings, other distributions and Wayland-specific behavior need deployment validation. Headless Linux CI uses Xvfb and disables the Chromium OS sandbox for the test process only; shipped launch settings do not disable the sandbox.

Local OpenRig on macOS/Linux requires a compatible installed OpenRig, Python 3 and tmux. The Doctor reports missing dependencies; HRig does not install them or launch agents automatically. SSH hosts remain supported on every desktop platform. GitHub CLI and Linear credentials must be configured on the machine running HRig. GitHub Projects remains read-only; issue changes and linked OpenRig assignments require explicit confirmation. Notification delivery, native desktop permission flows and real remote SSH tunnel endpoints remain deployment checks beyond the packaged smoke.

## Install or upgrade

Choose macos-arm64 for Apple Silicon, macos-x64 for Intel Macs, linux-x64 for ordinary Intel/AMD 64-bit Linux, or linux-arm64 for ARM Linux. Open the DMG and copy HRig to Applications, or extract its ZIP. On Linux, mark the AppImage executable before launching; the tar.gz download is available for systems where AppImage runtime support is unavailable. Keep the extracted Linux application directory together. Windows uses the portable executable as before.

Quit the previous HRig instance normally before upgrading. Settings/layouts and recovery copies live in the operating system's Electron user-data location; replacing application files does not modify project files or agent sessions. Back up user data before transferring it between operating systems, since local paths and encrypted credentials are host-specific.

## Integrity and source

All downloads are attached to the v0.8.1 source tag. SHA256SUMS includes the exact asset names and hashes for all nine application downloads. NATIVE-QA.json identifies the validated source commit and each platform/architecture's packaged checks. The publisher verifies local artifacts against their source manifests and GitHub's uploaded asset digests before making the release public. Existing tags and different uploaded artifacts are never overwritten. Full community-theme credits and licenses remain bundled.
