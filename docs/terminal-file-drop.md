# Dropping files onto terminals

Dropping onto a local terminal inserts the quoted local path without Enter. Dropping one regular file onto a connected SSH terminal asks in a native confirmation showing the host, the local source path (middle-truncated when long), temporary remote path, name and size. Confirm uploads at most 10 MiB over the existing SSH connection using stdin, then inserts the quoted POSIX path without Enter. Cancel sends no bytes and creates no remote file. Folders, links, devices, multiple SSH files, unsafe names and oversized files are refused with a visible message. WSL continues to refuse dropped files. The main process accepts only short-lived, one-use file tokens registered from a native dropped File through Electron's preload `webUtils.getPathForFile`; an arbitrary renderer-supplied path is refused.

Each upload uses `/tmp/hrig-upload-<uuid>/<filename>`, a private 0700 directory and exclusive 0600 file. The name is predictable from the confirmation and shell history; remove the file and its now-empty directory when finished. The transfer checks the received byte count against the selected file length and removes its newly created directory on a mismatch or transport failure. The app does not silently run the path or add it to diagnostics. The main process reads the local file after checking that it is a regular file, unchanged while read and within the cap. Upload starts a separate SSH process in BatchMode using the terminal's saved host and port; password, passphrase, 2FA and hardware-key-only hosts may fail. If you have hopped to another machine inside the terminal, the upload still goes to the configured host shown in the confirmation, not the machine reached from the shell.

Clipboard image paste uses the separate `terminal:paste-image` route (see [terminal-image-paste.md](terminal-image-paste.md)). It reads the clipboard in the main process, confirms the destination and size, then transfers over the existing connection. Both routes insert a path only; neither presses Enter. A real SSH host confirmation and resulting file must be checked by a person before claiming live-host behavior.
