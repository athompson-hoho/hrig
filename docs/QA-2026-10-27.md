## Additional exploratory checks

**Confirmed defect: Connection Doctor continues to display loading after failure.** In a fresh isolated Electron profile, replaced only that test process's `connection:doctor` IPC handler with a rejecting handler (`QA simulated unreachable host`). Opened Doctor through the command center. Both the error and `Checking connection and dependencies...` remained visible. `DoctorPanel` renders loading whenever `report` is null, including after rejection. Reproduce by rejecting the doctor request; acceptance is a terminal failed state with a retry action and no active loading indicator. No production IPC handler or application source was changed.

**Baseline keyboard behavior verified:** entering `New shell` in the command center and pressing Enter closes the dialog and activates the command. Do not report command Enter activation as missing. The existing handler also opens the first file match when no command matches; arrow-key result selection and fuzzy paths remain proposed extensions under HR-16.

## Coverage still needed

- Real SSH deployment: transport quoting is tested, but authentication lifecycle, host loss and managed forwarding need an isolated reachable SSH host. WSL fixtures do not prove this.
- Windows notification delivery, multi-monitor DPI changes, keyboard-only assistive workflows and Narrator need explicit deployment/manual checks. Narrow screenshots and monitor-bound recovery tests are narrower evidence.
- Mobile native Android/iOS builds and real LAN/Tailscale device behavior were not rerun here; browser tests cannot establish native storage, signing or background/resume behavior.
- Performance needs measurement with larger workspaces before optimization claims: current build emits an approximately 895 kB app chunk, 3.98 MB editor chunk and 7.03 MB TypeScript worker (uncompressed). Collect cold startup, editor-open latency, idle CPU and memory with 12/24 seats before setting budgets. Large emitted assets alone do not demonstrate a user-visible slowdown.
- Failure-path coverage should grow beyond success journeys: cancellation, stale responses, abrupt process loss, uncertain sends and stale review revisions are explicit acceptance targets in the proposed roadmap.

Recommendation: approve the reliability batch first (HR-11, HR-12, HR-17), followed by workspace convenience, then IDE depth. No implementation began during this review.
